# Конвейерный НОД и приоритетный шифратор

## Модуль 1 — `gcd_pipeline` (конвейерный НОД)

Выбран **бинарный алгоритм Евклида (алгоритм Стейна)** с конвейером из
`STAGES = 32` ступеней.

Почему:

- сходится гарантированно за `≤ 2·W` ступеней (для 16 бит максимум 31 — это
  подтверждено полным перебором всех пар чисел);
- на ступень нужны только вычитатель, компаратор и мультиплексоры — **без
  делителей**;

Принцип: каждая ступень делает один шаг — если оба числа чётные, сдвиг обоих
вправо с учётом общего множителя 2 в счётчике `cnt`; если чётное одно — сдвиг
его; если оба нечётные — вычитание меньшего из большего и сдвиг вправо. Итог
восстанавливается как `(a | b) << cnt`. Новая пара чисел принимается **каждый
такт**, результат выдаётся с задержкой `STAGES` тактов.

## Модуль 2 — `priority_encoder_16` (приоритетный шифратор, N = 16)

Выбрана **древовидная схема** из 4-входовых шифраторов `pe4` и узлов слияния
`merge`.

Почему:

- линейная оценка по числу LUT: для N = 16 теоретическая верхняя оценка
  **18 LUT6** (с (5,2)-упаковкой; консервативно без неё — **22 LUT**);
- структура регулярная и легко масштабируется на произвольное N.

Выход: `pos[3:0]` — номер старшего установленного бита, `valid` — признак
наличия единиц. В узле слияния старший бит номера равен признаку старшей группы:
`p_out = v_hi ? {1'b1, p_hi} : {1'b0, p_lo}`.

## Тестбенчи

### `tb_gcd_pipeline` — самопроверяющийся

Подаёт 85 560 пар подряд (по одной за такт, то есть проверяет и сквозную
пропускную способность конвейера). Ожидаемые значения считает эталонная функция
и сдвигает их по сдвиговому регистру глубиной `STAGES` — так учитывается задержка
конвейера; выход сверяется с ожиданием на каждом такте. Набор векторов: граничные
случаи (0, 1, 65535, степени двойки, худший случай), все пары 0..255 и случайные
пары. В конце печатает `PASS`/`FAIL`.

### `tb_priority_encoder_16` — исчерпывающий

Перебирает все `2^16` входов и сверяет выход с эталоном (поиск старшего
установленного бита простым перебором разрядов). В конце печатает `PASS`/`FAIL`.

## Как открыть проект

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/MrAngelos/Verilog-test-task.git
   cd Verilog-test-task
   ```
2. Откройте Vivado (проект создан в Vivado 2026.1).
3. **File → Open Project…** → выберите `project_1.xpr` в корне репозитория.
4. Исходники уже внутри репозитория (папки `sources_1/` и `sim_1/`) — Vivado подхватит их сам.

## Запуск симуляции

1. В дереве Sources выберите тестбенч (`tb_gcd_pipeline` или `tb_priority_encoder_16`)
   → ПКМ → **Set as Top**.
2. **Run Simulation → Run Behavioral Simulation**.
3. В Tcl-консоли выполните: `run all`
   (иначе по умолчанию симуляция пройдёт только 1000 нс и не дойдёт до конца).
4. Результат — в Tcl-консоли: `=== … PASS/FAIL ===`.

## Запуск синтеза (проверка числа LUT)

1. Установите top-модуль `priority_encoder_16` (или `gcd_pipeline`) → ПКМ → **Set as Top**.
2. **Run Synthesis** → число LUT смотрите в отчёте **Report Utilization** (вкладка Reports).
